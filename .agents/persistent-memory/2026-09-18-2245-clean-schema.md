# 2026-09-18-2245 — `clean` schema in the DuckDB

- **Author:** Javier Boix (with Claude Code)
- **When:** 2026-09-18

## What changed

- `analysis/clean_db.py` builds schema `clean` (same table names) next to the untouched `main` (raw). `build_db.py` runs it at the end. `clean.dq_log` lists each rule and rows affected.
- `score_pipeline.py` and both `.Rmd` files now `SET search_path = 'clean,main'`.

## Audit findings (raw data)

- Keys are unique everywhere; no orphan companies. Structural nulls only (`balances.available` 100% null, `transactions.counterparty_id` 90% null, `companies.country` 82% null).
- Transactions: 369 zero amounts; `value_date` in 2022/2023/2099 (650 rows >60 days from booking); 77 `exchange_rate = 0`; 25% category `-`; 105,642 repeated rows (4.1%, mostly small fees/card purchases with masked descriptions: kept, flagged `is_dup`); 24 rows |amount| >= 1e9 (incl. "Compensation for missing or excess Transactions" reconciliation plugs, kept); 29 products (1,314 tx) with no row in banking/debt_products.
- Invoices: `payment_date` is a placeholder (= due date) on 237k unpaid invoices and impossible (2000..6913, before issue, future) on 39k paid ones; 20,865 due dates before issue; `due_date` up to year 7025; 1,183 zero amounts; 3,501 same-currency rows with `exchange_rate <> 1`.
- Other: 36 free-text countries (ESPANA, Spain, Portugal...), 63 products created after the 2026-09-01 snapshot, 3 sentinel balances (-1e9, 9.99e10), 50 debts with |outstanding| > |granted|.

## Decisions

- Drop only rows without information (zero amounts). Never drop repeated or extreme transactions: balances are reconstructed from the full flow and the snapshot may include them.
- Impossible values -> NULL, doubtful -> flag. Unpaid-invoice `payment_date` set to NULL (it was a placeholder, not a payment).
- Effect on the score is negligible (panel 22,235 -> 22,230 rows; distribution unchanged): the pipeline already filtered these cases; the clean schema just makes it safe by default.
